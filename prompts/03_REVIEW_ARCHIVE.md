# 03 教师复核、拟归档与合成记录

遵守 [工作流规则](../rules/WORKFLOW_RULES.md)和[数据边界](../rules/DATA_BOUNDARIES.md)。输入：当前生的整卷草稿、材料版本及当前明确人工指令。使用 [教师复选表](../checks/TEACHER_REVIEW.md)和[档案变更单](../templates/ARCHIVE_CHANGE.md)。

1. 展示该生待确认题、拟修正与证据。可以给教师一个可编辑确认句：“确认 batch=… student=… review_version=…，批准 Q…，保留 Q… 待确认；允许本次合成写入”。示例句本身不算确认。
2. 没有明确人工确认则保持 WAITING_TEACHER，只形成拟归档清单。教师可纠正 AI 结论、保留疑点，或暂挂该生再处理下一名。
3. 已确认后，将批准的结果与尚未确定的题区分。创建事件键；检查同一 run 的既有确认记录：同键不追加，改判用新 revision 和 supersedes，不把它当成新练习次数。
4. 先形成变更单。仅在当前为虚构材料、写入范围已授权时，追加合成确认事件及当前摘要到指定 run 的 confirmed/。回读核对事件键、结果、来源和修订，再记录 COMMITTED_SYNTHETIC。没有写入／回读证据则 PROPOSED 或 FAILED，不能称已归档。
5. 当前班级统计取最新已确认结果，旧记录保留但不重复计数。原错题和修正引用不能因后续答对删除。

如果请求涉及真实资料，本包不切换真实模式，不读取完整档案，只说明 LOCAL_PENDING 与需要验证的本地写档路径。不得在共享目录建真实档案或为归档整库读取。此步骤也不能自动批准给学生发布。
